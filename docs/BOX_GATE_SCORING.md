# Box-gate ablation — reference scoring milestone

Completed 2026-10-23. The [registered ablation](BOX_GATE_ABLATION_PROTOCOL.md)
now has a development-only reference scorer for its [paired numeric inputs](BOX_GATE_INPUTS.md).
**No new tracker comparisons, candidate benefits or held-out results have been produced.**

## What this adds, in plain language

The input generator creates the practice questions. The scorer is the answer
checker: given a list of tracking rectangles and IDs, it measures what happened.
The next replay adapter will obtain those rectangles from the actual tracker.
This milestone tests the checker using deliberately constructed answers, not
outputs generated by either tracker variant.

It checks more than whether a rectangle was visible:

- Did an expected object receive a different local ID?
- Were object-frames missed, or extra rectangles reported?
- Did the same uninterrupted track actually cross the counting line?
- Was that crossing assigned to the correct direction and time window?
- How far was an observed or matched tracking anchor from its reference contact?

For example, our toy solo path crosses between frames 149 and 150. Hand-feeding
a different ID from frame 150 produces one ID switch and a missing crossing,
even though all 300 object-frames still have a matching rectangle. Removing
frame 149 instead produces a missed object-frame, fragmentation and a missing
crossing. The scorer does not reconnect either gap to flatter the result.

A second fixture moves the crossing two frames later: it is still a matched
crossing within the registered tolerance, but now falls in the next 30-frame
window. The old window is short by one and the new window has one extra, so
absolute window-count error is **two**, not zero. This is why visibility,
identity continuity, crossing detection and useful counts are separate measures.

## Implementation and boundaries

`experiments/box_gate_scoring.py` exposes `score_development(scene, public_rows)`:

1. Reject non-development inputs before generation. Verify both exact-byte
   protocol locks, regenerate the registered development input and compare
   every dataclass field and array's shape, dtype and bytes. A self-consistent
   caller-supplied hash alone is not trusted as input provenance.
2. Validate the bounded public-row schema: frame, positive local track ID,
   finite in-image positive-area box, score and class. Reject duplicate frame/ID
   pairs, extra truth fields and invalid values; do not silently discard rows.
3. Verify the production package's bytes against the registered baseline and
   check import origins before and after scoring. Use the existing canonical
   CLEAR-MOT evaluator's correspondence, retaining history across pulse and
   region boundaries. There is no new matching algorithm or per-stratum rematch.
4. Reuse unchanged parent crossing rules and pure geometry/summary helpers.
   Keep bottom-centre and secondary box-centre measurements separate. Regional
   false positives have no known reference region and remain null.
5. Retain all **37 inherited endpoints**, full failure/sample diagnostics,
   input/source/output fingerprints, and a self-excluding scoring-record hash.
   Missing matched timing or position is null, not zero error. Observation
   errors cover every reference object-frame; tracking position errors are
   conditional on a valid IoU match.

The outer record identifies the new ablation. Nested crossing records explicitly
retain the **parent recipe** ID/hashes because those rules are inherited, not
because these new paths belong to the opened original experiment.

The scorer neither constructs a tracker nor writes files, opens a held-out run,
chooses a variant or issues an acceptance verdict. Supplied rows can be
handcrafted; their fingerprint is **not proof of their producer**. The later
runner must establish source, configuration, actual detection handoff and
fresh/reset/fresh output equality. These workflow checks are not a sandbox for
malicious callers or concurrent in-process mutation.

The frozen original traffic study, new registration, production tracker and
Python/C++ parity fixtures remain unchanged. This is experiment-only code;
there is no production default change or C++ port.

## Verification

**65 scorer tests** use hand-fed rows and forbid tracker construction throughout
the new module. They cover all three development paths and four conditions,
analytically expected crossing times, all 37 endpoint names, canonical evaluator
agreement, gaps, ID changes, independent observation/tracked errors, false
positive strata, null handling, record ownership/hashes, every forged input
field, invalid public rows, source drift and import-origin rejection.

Run from the repository root:

```bash
python -m pytest tests/test_box_gate_scoring.py
```

These are tests of measurement correctness, **not tracking accuracy evidence**.
Toy numeric geometry and scheduled box errors do not establish real traffic
performance or whether disabling the rejection gate is useful.
